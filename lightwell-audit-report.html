Executive summary

The page is well-built at the craft level — clean semantics, one H1, real schema markup, HTTPS, honeypot spam protection, no leaked secrets. But three things pull the score down hard: there is no analytics on the site at all (zero pageview or conversion tracking of any kind), the security headers set at the server are silently dropped on the live page (they only appear on the HTTP→HTTPS redirect, not on the actual page you land on), and the site is a single 451-word page with no case studies, testimonials, or supporting content — thin for a consultancy asking $600–$3,500, and thin for both classic SEO and AI-answer-engine citation. The irony worth naming: this is a UX diagnostics business, and its own site has no instrumentation to diagnose itself.
01

SEO

6.5 /10

Technical foundation is solid — robots.txt, sitemap, canonical, one H1, alt text, semantic schema. The gaps are truncated metadata, a render-blocking third-party script, and a site too thin to earn topical authority.

HighTitle tag and meta description both exceed SERP display length
Issue

The <title> is 73 characters ("Lightwell | AI UX Diagnostics Reports for SaaS Product Teams | 72 Hours"); the meta description is ~230 characters. Google's practical cutoffs are ~60 and ~155–160.

Impact

Google truncates both mid-word in search results — the CTA and differentiators ("Fixed price, fully async, no meetings") likely get cut, weakening click-through.

Fix

Trim title to ≤60 chars, e.g. Lightwell | AI UX Diagnostics in 72 Hours. Trim description to ≤155 chars, front-loading the value prop before the truncation point.

HighRender-blocking 600KB+ script in <head>
Issue

three.js r128 is loaded synchronously from cdnjs in <head> with no defer/async, purely to drive a decorative hero shader.

Impact

Blocks first paint until a third-party CDN request completes — directly hurts LCP, a Core Web Vital Google uses as a ranking signal, and delays the point where the headline is visible.

Fix

Add defer to the script tag, or lazy-init the shader after DOMContentLoaded/on an IntersectionObserver for the hero. Consider self-hosting the single module actually used instead of the full three.js bundle.

MediumSingle-page site with 451 words of visible copy
Issue

Sitemap contains exactly one URL. There's no blog, no case study, no glossary/educational content, no comparison content — nothing for Google to index beyond the homepage.

Impact

No long-tail keyword coverage, no internal linking signal, no way to build topical authority around "AI UX," "AI feature adoption," or "AI product diagnostics." One page can rank for maybe one query.

Fix

Add 3–5 pages minimum: one real (anonymized) case study or before/after sample report, a short "how it works" / methodology page, and a couple of educational posts (e.g. "why users don't trust AI features," "how to diagnose AI feature adoption"). This also directly feeds AI-SEO (below).

MediumNo alt text audit trail for future images / decorative image reliance
Issue

Only two <img> elements exist on the whole page (logo, founder photo) — both currently have alt text, which is good, but there's no visual proof of the actual deliverable (a sample report screenshot, annotated screen example) that a prospect or an image-indexing crawler could find.

Impact

Low direct SEO impact today, but a missed opportunity: product screenshots with descriptive alt text are a cheap way to rank in Google Images and build trust.

Fix

Add 2–3 sample-deliverable screenshots (redacted findings report, annotated screen) with descriptive alt text.

What's already right

robots.txt is open (Allow: /) and correctly references the sitemap.
Self-referencing canonical tag present and correct.
Exactly one <h1>, clean H1→H2→H3 hierarchy with no skipped levels.
Valid ProfessionalService JSON-LD schema with structured Offer pricing.
HTTP→HTTPS 301 redirect in place; no mixed content.
02

AI-SEO (AEO / GEO)

3.5 /10

The weakest link relative to the business itself. A shop selling "AI UX diagnostics" has done nothing to make its own site legible to the AI systems its buyers increasingly search through.

HighNo llms.txt
Issue

/llms.txt returns 404. No machine-readable summary of what Lightwell does, who it's for, and what pages matter exists for AI crawlers/agents.

Impact

Answer engines (ChatGPT search, Perplexity, Claude, Gemini) have to infer everything from thin, unstructured HTML instead of a clean summary — lowering the odds of accurate citation or inclusion in a "best AI UX audit tools" style answer.

Fix

Add a concise llms.txt: what Lightwell is, the three tiers with prices, the 72-hour/async/fixed-price differentiators, and links to the highest-value pages.

HighNothing citable — no data, no case studies, no named outcomes
Issue

LLMs cite pages that contain specific, quotable claims (stats, before/after numbers, named methodology steps). The page currently has pricing and a process description, but no outcome data ("reduced onboarding drop-off by X%") or original research.

Impact

Generic marketing copy is exactly what LLMs are trained to compress and skip, not quote. Low odds of showing up as a cited source in an AI Overview or a Perplexity answer.

Fix

Publish one page with a concrete, specific claim per completed engagement (with permission) — a number, a screenshot, a before/after. Even one strong case study is disproportionately valuable for citation.

MediumSingle schema type — no FAQPage, no Person, no Organization
Issue

Only one JSON-LD block exists (ProfessionalService). The founder is named in prose and in schema as a sub-property, but there's no standalone Person entity, no Organization, and the "which tier fits" content isn't marked up as FAQ despite reading like Q&A.

Impact

Structured data is one of the clearest signals LLMs use to extract entities and facts confidently. More schema depth = more accurate machine understanding of who Frank is, what the service costs, and what questions it answers.

Fix

Add FAQPage schema around the tier-selection content, a standalone Person entity for the founder linked via sameAs to LinkedIn/Contra, and top-level Organization schema.

What's already right

robots.txt doesn't block AI crawlers (GPTBot, ClaudeBot, PerplexityBot) — wildcard allow covers them.
Existing ProfessionalService schema does give a machine-readable price range and offer list — a real head start most competitors skip.
03

Engagement & conversion

5.5 /10

The qualifier-quiz → tier-recommendation → payment-link flow is a genuinely good conversion pattern. The gaps are in trust-building and failure handling.

HighZero social proof anywhere on the page
Issue

No testimonials, client logos, review counts, or named outcomes appear anywhere in the 451 words of copy.

Impact

For a $600–$3,500 async purchase from a solo practitioner, absence of social proof is one of the highest-friction trust gaps in the funnel — visitors have no evidence anyone has bought this and been satisfied.

Fix

Add even 2–3 short quotes with name/title/company (or "anonymized SaaS PM" if NDA'd), plus a link to the sample report already referenced (the Notion "preview the intake form" link should sit next to a preview of the actual *output*, not just the intake).

MediumLead form fails silently
Issue

The qualifier form's fetch('/', …) POST to Netlify Forms has a .catch() that only does console.error. The payment-link tab opens regardless of whether the lead data actually saved, and the visitor is never told either way.

Impact

If the Netlify submission fails (network blip, form-name mismatch, ad blocker), the qualifying answers (which tier, what they want reviewed) are silently lost — Frank loses context on a paying lead with no way to know it happened.

Fix

Await the fetch before opening the payment link, and show a small inline confirmation ("Got it — check your email") or a fallback ("Having trouble? Email frank@…") on failure.

MediumCheckout is a same-tab-losing external redirect
Issue

Payment happens on Contra's domain via window.open(..., '_blank'), not on lightwellhq.com. The original tab is left showing the recommendation screen with no indication payment is in progress elsewhere.

Impact

Split-tab checkout is a known source of drop-off — the visitor has to notice the new tab, and if they close the original tab first there's no path back.

Fix

Add a visible "Complete your purchase in the new tab →" state on the original page instead of leaving it static, and/or link a direct anchor for return.

What's already right

The qualifier quiz → tier recommendation pattern reduces decision paralysis better than a flat three-column pricing table.
Honeypot field (bot-field) present on the form for spam filtering.
Client-side email/required-field validation with inline, specific error text (not just "invalid input").
04

Analytics

0.5 /10

There is none. Checked the full rendered HTML for GA4/gtag, GTM, Meta/LinkedIn pixels, Hotjar, Clarity, Plausible, Fathom, Segment, PostHog, Mixpanel — no matches for any of them.

CriticalNo analytics or tracking of any kind is installed
Issue

No pageview analytics, no event tracking, no conversion pixel, no session-replay tool. There's also no UTM capture in the lead form (q1/q2/q3/tier are recorded, but not utm_source/utm_medium/referrer), and no click tracking on the outbound Contra payment links before window.open fires.

Impact

There is currently no way to answer: how much traffic the site gets, where it comes from, what the qualifier-quiz completion rate is, which tier gets recommended most, or how many "Book" clicks actually convert to a paid Contra checkout. Every marketing decision (SEO investment, ad spend, copy changes) is happening blind. For a business whose entire product is instrumented diagnosis of other people's funnels, this is the most fixable and highest-leverage gap on the list.

Fix

Minimum viable setup: (1) a privacy-friendly analytics tool (Plausible or Fathom fit this site's size and avoid a cookie-consent banner) for pageviews/referrers; (2) event tracking on quiz start, quiz complete, tier recommendation shown, and each "Book" click; (3) capture utm_* params and referrer into the existing Netlify form payload so lead source is known; (4) if paid channels are ever used, add server-side conversion tracking (Meta CAPI / GA4 measurement protocol) since the actual purchase happens off-domain on Contra and client-side pixels alone would miss it.

05

Security

6.0 /10

No leaked secrets, sound CORS posture, good rel="noopener" hygiene on external links. One real, meaningful misconfiguration: the security headers aren't actually reaching the page visitors load.

CriticalCSP, HSTS, X-Frame-Options, and Referrer-Policy are configured — but not served on the live page
Issue

A full, well-written security header set (CSP, Strict-Transport-Security, X-Frame-Options: DENY, X-Content-Type-Options, Referrer-Policy, Permissions-Policy) is present on the http:// → https:// 301 redirect response only. The actual https://lightwellhq.com/ page that visitors and Googlebot land on returns only content-type, server, and rate-limit headers — none of the protective headers.

Impact

The page as actually served has no clickjacking protection (X-Frame-Options/frame-ancestors absent), no enforced CSP (so if a third-party script were ever compromised or injected, nothing would block it), and MIME-sniffing protection is off. HSTS not being resent on every response is lower-risk once a browser has cached it once, but it means the policy isn't durable across host/CDN changes. This looks like a redirect-only rule in the hosting config (Apache/CDN) rather than an app-level omission — worth checking whoever manages the header config, since the fix is one rule, not a code change.

Fix

Move the header block from the redirect rule to apply on every response for the domain (in Apache: a global Header set or <IfModule mod_headers.c> block outside the redirect-only vhost/rewrite condition). Re-verify with curl -sI https://lightwellhq.com/ that CSP/HSTS/X-Frame-Options/Referrer-Policy/Permissions-Policy all appear on the 200 response, not just the 301.

What's already right

No API keys, tokens, or secrets found anywhere in page source.
Every target="_blank" link correctly carries rel="noopener" — no reverse-tabnabbing exposure.
Third-party script (three.js) is loaded with a Subresource Integrity hash, so a compromised CDN file can't silently execute.
Lead form has honeypot spam protection and is a same-origin POST — no unnecessary CORS surface.
The (misapplied, but well-designed) CSP itself is a reasonable starting policy once it's actually applied to the right response.
